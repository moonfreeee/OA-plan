## 1. 引言

### 1.1 编写目的

本文档描述「软件开发办公室内部管理系统」在当前开发版本（`dev` 分支）下的完整功能规格、系统架构、数据模型与接口约定，作为项目交付、验收与后续维护的统一参考。

### 1.2 项目背景

软件开发办公室（SDO）需要一套 Web 平台，用于统一管理成员账号、团队项目、日常打卡、周期性考核、内部培训课程与公告通知。系统面向办公室成员与管理员两类用户，采用 B/S 架构，支持本地开发与 Mock 演示两种运行模式。

### 1.3 术语与缩略语

| 术语 | 含义 |
|------|------|
| OA | Office Automation，办公自动化 |
| B/S | Browser/Server，浏览器/服务器架构 |
| JWT | JSON Web Token，用于无状态身份认证 |
| Mock | 前端本地模拟数据模式，无需启动后端与数据库 |

- `docs/01-需求规格说明书.md` — 初始需求（部分功能已在实现中调整）

## 2. 系统概述

### 2.1 系统目标

1. 为办公室成员提供统一的个人信息、团队、考核、课程与打卡入口。
2. 为管理员提供账号生命周期管理、审核流程与业务数据维护能力。
3. 通过 REST API 实现前后端分离，便于扩展与部署。

### 2.2 技术架构

```
┌─────────────────────────────────────────┐
│  表现层：Vue 3 + Vite + Element Plus    │
│  路由：Vue Router  │  状态：Pinia        │
└──────────────────┬──────────────────────┘
                   │ HTTP/JSON（/api/v1）
┌──────────────────▼──────────────────────┐
│  业务层：Node.js + Express              │
│  认证：JWT + bcrypt  │  校验：express-validator │
└──────────────────┬──────────────────────┘
                   │ mssql（参数化查询）
┌──────────────────▼──────────────────────┐
│  数据层：Microsoft SQL Server（SDO_OA） │
└─────────────────────────────────────────┘
```

### 2.3 运行模式

| 模式 | 配置 | 说明 |
|------|------|------|
| Mock 演示 | `frontend/.env.development` 中 `VITE_USE_MOCK=true` | 仅启动前端即可浏览全部页面 |
| 真实后端 | `VITE_USE_MOCK=false` | 需同时启动 Express 后端与 SQL Server |

### 2.4 默认服务地址

| 服务 | 地址 |
|------|------|
| 前端开发服务器 | http://localhost:5173 |
| 后端 API | http://localhost:3000 |
| API 前缀 | `/api/v1` |
| 健康检查 | `GET /api/v1/health` |

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 标识 | 说明 |
|------|------|------|
| 管理员 | `admin` | 拥有系统管理菜单及全部管理端功能 |
| 成员 | `member` | 使用业务功能，不可访问 `/admin/*` 路由 |

### 3.2 账号状态

| 状态 | 标识 | 说明 |
|------|------|------|
| 待审核 | `pending` | 不可登录，需管理员审核 |
| 正常 | `active` | 可正常登录使用系统 |
| 已拒绝 | `rejected` | 不可登录 |

> **说明**：当前版本已取消成员自助注册。新账号由管理员在「账号管理」中创建；原注册入口已改为「密码找回」申请流程。

### 3.3 演示账号

| 用户名 | 密码 | 角色 | 用途 |
|--------|------|------|------|
| admin | Admin@123 | 管理员 | 管理端全功能演示 |
| member1 | Member@123 | 成员 | 成员端功能演示 |

## 4. 功能规格

### 4.1 用户认证

#### 4.1.1 登录

| 编号 | 功能 | 描述 |
|------|------|------|
| FR-A01 | 用户登录 | 支持用户名或邮箱 + 密码登录，成功后返回 JWT 与用户信息 |
| FR-A02 | 状态校验 | `pending` / `rejected` 账号拒绝登录并给出明确提示 |
| FR-A03 | 会话保持 | Token 存储于前端，请求头携带 `Authorization: Bearer <token>` |

**页面路径**：`/login`

#### 4.1.2 密码找回（管理员审核）

| 编号 | 功能 | 描述 |
|------|------|------|
| FR-A04 | 提交找回申请 | 成员填写账号、新密码、确认密码，提交后进入待审核状态 |
| FR-A05 | 重复申请限制 | 同一用户存在 `pending` 申请时不可重复提交 |
| FR-A06 | 管理员审核 | 管理员在「密码找回审核」中批准或拒绝；批准后密码立即生效 |

**页面路径**：`/login?tab=reset`（原 `/register`、`/forgot-password` 已重定向至此）

#### 4.1.3 账号管理（管理员）

| 编号 | 功能 | 描述 |
|------|------|------|
| FR-A07 | 创建账号 | 管理员填写用户名、密码、姓名、联系方式、邮箱、学号等创建成员账号 |
| FR-A08 | 编辑账号 | 修改成员基本信息（不含密码，密码通过找回流程变更） |
| FR-A09 | 删除账号 | 删除指定成员账号 |
| FR-A10 | 审核待审用户 | 对 `pending` 状态用户执行通过或拒绝（保留兼容接口） |

**页面路径**：`/admin/accounts`

## 6. 数据模型

数据库名：**SDO_OA**。完整 DDL 见 `database/schema.sql`。

### 6.1 实体一览

| 表名 | 说明 |
|------|------|
| Users | 用户账号（角色、状态、个人信息） |
| PasswordResetRequests | 密码找回申请（管理员审核） |
| PasswordResetCodes | 验证码表（历史遗留，Mock/旧流程保留） |
| Announcements | 公告 |
| Teams | 项目团队 |
| TeamMembers | 团队成员关联 |
| TeamMembershipRequests | 加入/退出团队申请 |
| TeamTasks | 团队任务（todo/doing/done） |
| AssessmentPeriods | 考核周期 |
| AssessmentScores | 考核成绩（四维评分） |
| Courses | 课程 |
| CourseChapters | 课程章节 |
| LearningProgress | 章节学习进度 |
| ClockInRecords | 每日打卡记录 |

### 6.2 核心实体关系

```
Users ─┬─< TeamMembers >── Teams
       ├─< TeamMembershipRequests >── Teams
       ├─< TeamTasks（creator/assignee）
       ├─< AssessmentScores >── AssessmentPeriods
       ├─< LearningProgress >── CourseChapters >── Courses
       ├─< ClockInRecords
       ├─< PasswordResetRequests
       └─< Announcements（publisher）

Teams ──< TeamTasks
```

### 6.3 数据库迁移

增量迁移脚本位于 `database/migrations/`：

| 文件 | 内容 |
|------|------|
| `001_clock_in.sql` | 打卡记录表 |
| `002_password_reset_requests.sql` | 密码找回申请表 |

### 6.4 数据初始化

| 方式 | 命令/脚本 | 说明 |
|------|-----------|------|
| 全量重建（推荐） | `cd backend && npm run reset-db` | 执行 schema + seed.js |
| 种子脚本 | `backend/scripts/seed.js` | 使用 bcrypt 正确写入密码哈希 |
| PowerShell 辅助 | `backend/scripts/init-db.ps1` | Windows 环境数据库初始化 |

> **注意**：请勿使用 `sqlcmd` 直接执行 `database/seed.sql`，bcrypt 哈希中的 `$` 字符可能导致编码/转义问题。

## 7. 接口规格

### 7.1 通用约定

**请求头**（需认证接口）：
```
Authorization: Bearer <JWT>
Content-Type: application/json
```

**响应格式**：
```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| code | 含义 |
|------|------|
| 0 | 成功 |
| 非 0 | 业务错误或异常（message 含具体说明） |

### 7.2 认证接口 `/api/v1/auth`

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/login` | 公开 | 登录，返回 token 与 user |
| POST | `/password-reset-request` | 公开 | 提交密码找回申请 |

### 7.3 用户接口 `/api/v1/users`

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/me` | 登录 | 当前用户信息 |
| PUT | `/me` | 登录 | 更新个人信息 |
| PUT | `/me/password` | 登录 | 修改密码 |
| GET | `/me/summary` | 登录 | 考核/学习摘要 |

## 8. 非功能需求

### 8.1 性能

- 实验环境下页面首屏加载与 API 响应时间目标 < 3 秒。
- 数据库查询使用索引（用户名、邮箱、团队关联、考核关联、打卡日期等）。

### 8.2 安全

| 措施 | 实现 |
|------|------|
| 密码存储 | bcrypt 哈希（cost factor 10） |
| 身份认证 | JWT，默认有效期 24h |
| SQL 注入防护 | mssql 参数化查询 |
| 权限控制 | 后端 `requireAuth` + `requireRole('admin')` 中间件；前端路由 `meta.roles` 守卫 |
| 敏感配置 | `backend/.env` 不纳入版本控制 |

### 8.3 可用性

- 支持 Chrome、Edge 等现代浏览器。
- 左侧导航结构清晰，管理端与成员端菜单分离。
- 网络/后端不可达时前端给出友好错误提示。

### 8.4 可维护性

- 前后端分离，RESTful API 统一前缀与响应格式。
- 数据库 schema 与迁移脚本分离，支持增量升级。
- Mock 层（`frontend/src/mock/`）与真实 API 可通过环境变量切换。
