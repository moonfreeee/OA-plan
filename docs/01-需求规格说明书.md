# 需求规格说明书

## 1. 引言

### 1.1 编写目的

本文档描述「软件开发办公室内部管理系统」的功能需求与非功能需求，作为设计、开发与测试的依据。

### 1.2 项目背景

软件开发办公室需要一套 Web 平台，统一管理成员信息、团队项目、周期性考核与内部培训课程。

### 1.3 定义与缩略语

- OA：Office Automation，办公自动化
- JWT：JSON Web Token
- B/S：Browser/Server 浏览器/服务器架构

## 2. 可行性分析

### 2.1 技术可行性

采用 Vue 3 + Express + SQL Server 成熟技术栈，开发工具完善，单人可在实验周期内完成。

### 2.2 经济可行性

全部使用开源框架与已有 SQL Server 环境，无额外授权成本。

### 2.3 操作可行性

Web 界面直观，左侧导航清晰，成员与管理员角色分离，易于上手。

## 3. 功能需求

### 3.1 用户认证

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-A01 | 用户注册 | 填写用户名、邮箱、密码、姓名、学号，注册后待审核 |
| FR-A02 | 用户登录 | 用户名/邮箱 + 密码登录，JWT 认证 |
| FR-A03 | 重置密码 | 邮箱验证码（实验环境模拟）重置密码 |
| FR-A04 | 用户审核 | 管理员审核 pending 用户 |

### 3.2 首页仪表盘

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-D01 | 统计卡片 | 展示团队数、进行中课程、待完成考核、公告数 |
| FR-D02 | 公告列表 | 展示最新 5 条公告 |
| FR-D03 | 近期动态 | 展示考核、任务、学习进度更新 |

### 3.3 个人中心

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-P01 | 信息维护 | 编辑姓名、手机、头像、简介 |
| FR-P02 | 修改密码 | 验证旧密码后修改 |
| FR-P03 | 考核/学习摘要 | 展示最近考核均分与课程进度 |

### 3.4 考核系统

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-AS01 | 考核周期 | 管理员创建周期（草稿/进行中/已结束） |
| FR-AS02 | 四维评分 | 技术、协作、态度、贡献（0-100） |
| FR-AS03 | 成绩查看 | 成员仅查看已发布成绩 |

### 3.5 我的团队

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-T01 | 团队列表 | 展示所属团队 |
| FR-T02 | 团队详情 | 成员列表、项目描述 |
| FR-T03 | 任务看板 | 待办/进行中/已完成三列 |
| FR-T04 | 任务管理 | 负责人/admin 创建任务，成员更新状态 |

### 3.6 课程学习

| 编号 | 需求 | 描述 |
|------|------|------|
| FR-C01 | 课程列表 | 分类、难度、进度展示 |
| FR-C02 | 章节学习 | 章节内容与完成标记 |
| FR-C03 | 进度计算 | 自动计算课程完成百分比 |

## 4. 非功能需求

- **性能**：页面响应 < 3 秒（实验环境）
- **安全**：密码 bcrypt 哈希，JWT 认证，参数化 SQL
- **可用性**：支持 Chrome/Edge 现代浏览器
- **可维护性**：前后端分离，REST API 规范

## 5. 用例图（文字描述）

### 顶层用例

参与者：成员、管理员

用例：登录、注册、重置密码、查看仪表盘、个人中心、考核、团队、课程、系统管理

### 认证子系统分解

- 注册 → 填写信息 → 等待审核
- 登录 → 验证凭证 → 进入系统
- 重置密码 → 请求验证码 → 确认新密码

### 考核子系统分解

- 管理员：创建周期 → 录入成绩 → 发布
- 成员：查看已发布成绩
