## 2. 公共基础设施

### 2.1 认证中间件（`middleware/auth.js`）

#### 2.1.1 算法：JWT 校验

```
算法 RequireAuth(request):
  1. 从 Header 读取 Authorization
  2. 若不存在或不以 "Bearer " 开头 → 返回 401
  3. token ← Header 去掉前 7 字符
  4. 尝试 jwt.verify(token, JWT_SECRET)
     4.1 成功 → req.user ← 解码载荷 { userId, username, role }，继续 next()
     4.2 失败 → 返回 401 "Token 已过期或无效"

算法 RequireRole(roles[]):
  1. 若 req.user.role 不在 roles 中 → 返回 403
  2. 否则 next()
```

#### 2.1.2 数据结构

```javascript
// JWT 载荷（req.user）
{
  userId: number,    // 对应 Users.user_id
  username: string,
  role: 'admin' | 'member'
}
```

#### 2.1.3 接口

本模块不对外暴露 HTTP 接口，作为 Express 中间件挂载于各路由。

### 2.2 数据库访问层（`config/db.js`）

#### 2.2.1 算法：连接池与参数化查询

```
算法 GetPool():
  1. 若全局 pool 已存在 → 直接返回
  2. 根据 DB_USE_WINDOWS_AUTH 选择连接方式
     2.1 Windows 认证（需 msnodesqlv8）→ trustedConnection = true
     2.2 SQL 认证 → 使用 DB_USER / DB_PASSWORD
  3. pool ← mssql.connect(config)，max=10
  4. 返回 pool

算法 Query(sqlText, params):
  1. p ← GetPool()
  2. request ← p.request()
  3. 对 params 中每个 (key, value) 调用 request.input(key, value)
  4. 执行 request.query(sqlText)，返回 recordset
```

#### 2.2.2 数据结构

```javascript
// 连接池配置 config
{
  server: string,
  port: number,
  database: 'SDO_OA',
  user?: string,
  password?: string,
  options: { encrypt, trustServerCertificate, trustedConnection },
  pool: { max: 10, min: 0, idleTimeoutMillis: 30000 }
}

// 查询结果
{ recordset: Array<Row>, rowsAffected: number[] }
```

### 2.3 前端 HTTP 层（`api/request.js`）

#### 2.3.1 算法：请求/响应拦截

```
算法 RequestInterceptor(config):
  1. token ← localStorage.getItem('token')
  2. 若 token 存在 → config.headers.Authorization = "Bearer " + token
  3. 返回 config

算法 ResponseInterceptor(response):
  1. res ← response.data
  2. 若 res.code ≠ 0 → 弹出错误消息，reject
  3. 否则返回 res（含 data 字段）

算法 ErrorInterceptor(error):
  1. 若 HTTP 401 → 清除 token/user，跳转 /login
  2. 若无 response 或网络错误 → 提示"无法连接后端服务..."
  3. 弹出错误消息，reject
```

#### 2.3.2 数据结构

```javascript
// Pinia user store（stores/user.js）
{
  state: {
    user: User | null,
    token: string
  },
  getters: {
    isLoggedIn: boolean,
    isAdmin: boolean
  }
}

// User 前端对象
{
  user_id, username, email, role, status,
  real_name, student_no, phone, avatar, bio, created_at
}
```

### 3.1 认证模块（Auth）

**后端文件**：`backend/src/routes/auth.js`  
**前端页面**：`frontend/src/views/auth/AuthEntryView.vue`

#### 3.1.1 模块职责

处理用户登录与密码找回申请提交；不处理自助注册。

#### 3.1.2 算法

**算法 Login(account, password)**：

```
1. 参数校验：account、password 非空
2. 查询 Users WHERE username = account OR email = account
3. 若用户不存在 → 返回 401 "用户名或密码错误"
4. bcrypt.compare(password, user.password_hash)
   4.1 不匹配 → 返回 401
5. 检查 user.status:
   5.1 pending → 返回 403 "账号待审核"
   5.2 rejected → 返回 403 "账号已被拒绝"
6. token ← jwt.sign({ userId, username, role }, JWT_SECRET, expiresIn)
7. 删除 password_hash，返回 { token, user }
```

**算法 PasswordResetRequest(account, new_password, confirm_password)**：

```
1. 参数校验：account 非空，new_password 长度 ≥ 6，confirm 一致
2. 查询用户，不存在 → 返回错误
3. 若 status ≠ active → 返回 "账号状态异常"
4. 查询 PasswordResetRequests WHERE user_id AND status='pending'
   4.1 存在 → 返回 "已有待审核申请"
5. password_hash ← bcrypt.hash(new_password, 10)
6. INSERT PasswordResetRequests (user_id, new_password_hash, status='pending')
7. 返回成功消息
```

**密码哈希算法**：bcrypt，cost factor = 10。

**JWT 签发算法**：HS256，payload 含 `userId`、`username`、`role`，默认有效期 24h。

#### 3.1.3 数据结构

| 结构 | 字段 | 说明 |
|------|------|------|
| Users（表） | user_id, username, email, password_hash, role, status, real_name, student_no, phone, avatar, bio, created_at, updated_at | 用户主表 |
| PasswordResetRequests（表） | request_id, user_id, new_password_hash, status, created_at, reviewed_at, reviewer_id | 密码找回申请 |
| LoginRequest（DTO） | account, password | 登录请求体 |
| LoginResponse（DTO） | token, user | 登录响应 data |
| ResetRequest（DTO） | account, new_password, confirm_password | 找回申请请求体 |

#### 3.1.4 接口细节

##### POST `/api/v1/auth/login`

| 项 | 内容 |
|----|------|
| 权限 | 公开 |
| 请求体 | `{ "account": "admin", "password": "Admin@123" }` |
| 成功响应 data | `{ "token": "eyJ...", "user": { user_id, username, email, role, status, real_name, ... } }` |
| 错误码 | 401 凭证错误；403 账号 pending/rejected |

### 3.2 用户与账号管理模块（Users）

**后端文件**：`backend/src/routes/users.js`

成员个人信息维护、密码修改；管理员账号 CRUD 与密码找回审核。

#### 3.2.2 算法

**算法 UpdateProfile(userId, fields)**：

```
1. 使用 COALESCE 部分更新 real_name, phone, avatar, bio
2. updated_at ← GETDATE()
3. 重新查询并返回用户对象
```

**算法 ChangePassword(userId, old_password, new_password)**：

```
1. 查询当前 password_hash
2. bcrypt.compare(old_password, hash) → 失败则返回错误
3. new_hash ← bcrypt.hash(new_password, 10)
4. UPDATE Users SET password_hash = new_hash
```

**算法 CreateUserByAdmin(fields)**：

```
1. 校验 username(3-50)、email 格式、password(≥6)、real_name、phone 非空
2. 查重 username OR email → 冲突则失败
3. password_hash ← bcrypt.hash(password, 10)
4. INSERT Users (role='member', status='active', ...)
5. OUTPUT INSERTED 返回新用户
```

**算法 ReviewPasswordReset(requestId, action, reviewerId)**：

```
1. 查询 request WHERE request_id AND status='pending'
2. 不存在 → 404
3. UPDATE request SET status=approved|rejected, reviewed_at, reviewer_id
4. 若 action=approve:
     UPDATE Users SET password_hash = request.new_password_hash
5. 返回操作结果消息
```

**算法 GetUserSummary(userId)**：

```
1. 查询 TOP 3 已发布考核成绩，按 end_date DESC
   avg_score = (tech + team + attitude + contribution) / 4
2. 查询各已发布课程进度：
   progress_pct = COUNT(completed chapters) / COUNT(total chapters) × 100
3. 返回 { assessments[], learning[] }
```

### 3.3 仪表盘与打卡模块（Dashboard）

**后端文件**：`backend/src/routes/dashboard.js`  
**前端页面**：`DashboardView.vue`、`admin/ClockInView.vue`

#### 3.3.1 模块职责

聚合首页统计数据、公告、动态；成员每日打卡；管理员查看全员打卡。

#### 3.3.2 算法

**算法 GetDashboardSummary(userId)**：

```
1. teamCount ← COUNT(TeamMembers WHERE user_id)
2. courseInProgress ← COUNT(已发布课程 WHERE 存在未完成章节)
   判定：COUNT(chapters) > COUNT(completed chapters for user)
3. pendingAssessment ← COUNT(active 周期 WHERE 用户无已发布成绩)
4. announcementCount ← COUNT(Announcements)
5. recentAnnouncements ← TOP 5 ORDER BY created_at DESC
6. activities ← UNION ALL 三类动态，TOP 10 ORDER BY time DESC:
   - 已发布考核更新
   - 所属团队任务变更
   - 章节学习完成
7. 返回 { stats, announcements, activities }
```

**算法 ClockIn(userId)**：

```
1. today ← CAST(GETDATE() AS DATE)
2. 查询 ClockInRecords WHERE user_id AND clock_date = today
3. 若已存在 → 返回 400 "今日已打卡"
4. INSERT (user_id, clock_date=today, clock_in_time=GETDATE())
5. 返回 { clockedIn: true, clockInTime }
```

**算法 GetTodayClockIns()（管理员）**：

```
1. LEFT JOIN Users 与 ClockInRecords（clock_date = today）
2. 仅 status='active' 用户
3. ORDER BY clocked_in DESC, clock_in_time ASC, real_name
4. 统计 clocked_count, absent_count
5. 返回 { date, total, clocked_count, absent_count, records[] }
```

#### 3.3.3 数据结构

| 结构 | 字段 |
|------|------|
| ClockInRecords（表） | record_id, user_id, clock_date, clock_in_time |
| DashboardStats | teamCount, courseInProgress, pendingAssessment, announcementCount |
| ActivityItem | type, title, detail, time |
| ClockInStatus | clockedIn: boolean, clockInTime: datetime \| null |
| TodayClockInReport | date, total, clocked_count, absent_count, records[] |

**唯一约束**：`UQ_ClockIn_UserDate (user_id, clock_date)` 保证幂等。

### 3.4 团队管理模块（Teams）

**后端文件**：`backend/src/routes/teams.js`  
**前端页面**：`TeamsView.vue`、`TeamOverviewView.vue`、`TeamDetailView.vue`、`admin/TeamsView.vue`

#### 3.4.1 模块职责

团队 CRUD、成员管理、加入/退出申请审核、任务看板。

#### 3.4.2 算法

**算法 ComputeMembershipStatus(userId, teams[])**：

```
输入：全部团队列表、用户 join/leave pending 申请、用户已加入团队
1. joinSet ← Set(pending join team_ids)
2. leaveSet ← Set(pending leave team_ids)
3. memberSet ← Set(joined team_ids)
4. 对每个团队 t:
   IF t.team_id ∈ memberSet:
     IF t.team_id ∈ leaveSet → status = 'exit_pending'
     ELSE → status = 'joined'
   ELSE IF t.team_id ∈ joinSet → status = 'pending'
   ELSE → status = 'none'
5. 返回带 membership_status 的团队列表
```

**算法 CanManageTeam(userId, role, teamId)**：

```
IF role = 'admin' → true
ELSE IF Teams.leader_id = userId → true
ELSE → false
```

**算法 ReviewMembershipRequest(requestId, action)**：

```
1. 查询 pending 申请 row
2. UPDATE status = approved | rejected
3. IF approved:
   IF row.type = 'join':
     IF NOT EXISTS TeamMembers → INSERT
   IF row.type = 'leave':
     DELETE FROM TeamMembers
4. 返回消息
```

**算法 UpdateTask(teamId, taskId, userId, role, body)**：

```
1. 查询任务，不存在 → 404
2. canManage ← CanManageTeam(userId, role, teamId)
3. isAssignee ← task.assignee_id = userId
4. IF NOT canManage AND NOT isAssignee → 403
5. IF NOT canManage AND (修改 title/description/assignee) → 403
6. COALESCE 更新字段，updated_at ← GETDATE()
```

**任务状态机**：

```
todo ──开始──→ doing ──完成──→ done
（status 字段 CHECK IN ('todo','doing','done')）
```

| TeamTasks | task_id, team_id, title, description, status, assignee_id, creator_id |
| TeamOverviewItem | Team + member_count + leader_name + membership_status |
| TeamDetail | Team + members[] + tasks[] |

### 3.5 考核管理模块（Assessments）

**后端文件**：`backend/src/routes/assessments.js`  
**前端页面**：`AssessmentView.vue`、`admin/AssessmentsView.vue`

#### 3.5.1 模块职责

考核周期管理、四维成绩录入/发布、成员按时间轴查询历史成绩。

#### 3.5.2 算法

**算法 CalculateAvgScore(tech, team, attitude, contribution)**：

```
avg = (ISNULL(tech,0) + ISNULL(team,0) + ISNULL(attitude,0) + ISNULL(contribution,0)) / 4.0
返回 avg（SQL 层计算，保留一位小数展示由前端处理）
```

**算法 QueryPeriodsByDate(year?, month?, day?)**：

```
1. 基础 SQL: SELECT FROM AssessmentPeriods WHERE 1=1
2. IF year  → AND YEAR(end_date) = year
3. IF month → AND MONTH(end_date) = month
4. IF day   → AND DAY(end_date) = day
5. ORDER BY start_date DESC
说明：以周期 end_date 作为时间轴筛选基准
```

**算法 UpsertScore(period_id, user_id, scores, published)**：

```
1. 查询 AssessmentScores WHERE period_id AND user_id
2. IF 存在 → UPDATE 四维分数、comment、published
3. ELSE → INSERT 新记录
4. 唯一约束 UQ_AssessmentScore(period_id, user_id) 保证不重复
```

**考核周期状态机**：

```
draft ──启动──→ active ──结束──→ closed
```

#### 3.5.3 数据结构

| 结构 | 字段 |
|------|------|
| AssessmentPeriods | period_id, title, start_date, end_date, status(draft/active/closed) |
| AssessmentScores | score_id, period_id, user_id, tech_score, team_score, attitude_score, contribution_score, comment, published |
| ScoreWithAvg | AssessmentScores + avg_score + period_title |
| DateFilter | `{ year?: number, month?: number, day?: number }` |

**分数约束**：各维度 CHECK BETWEEN 0 AND 100。

### 3.6 课程学习模块（Courses）

**后端文件**：`backend/src/routes/courses.js`  
**前端页面**：`CoursesView.vue`、`CourseDetailView.vue`、`admin/CoursesView.vue`

#### 3.6.1 模块职责

课程与章节 CRUD、学习进度跟踪与完成率计算。

#### 3.6.2 算法

**算法 CalculateProgress(userId, courseId)**：

```
total ← COUNT(CourseChapters WHERE course_id)
done ← COUNT(LearningProgress JOIN chapters WHERE user_id AND course_id)
progress_pct ← total > 0 ? ROUND(done / total × 100) : 0
```

**算法 MarkChapterComplete(userId, chapterId)**：

```
IF NOT EXISTS LearningProgress(user_id, chapter_id):
  INSERT LearningProgress (user_id, chapter_id, completed_at=GETDATE())
ELSE:
  无操作（幂等）
```

**算法 ListCourses(userId, isAdmin)**：

```
1. 查询 Courses（成员仅 published；admin 可见全部）
2. 子查询 chapter_count、learner_count
3. 若非 admin，附加 my_progress 百分比
4. ORDER BY created_at DESC
```

**进行中课程判定**（用于仪表盘）：

```
HAVING COUNT(chapters) > COUNT(completed chapters for user)
即：存在未完成章节的已发布课程
```

#### 3.6.3 数据结构

| 结构 | 字段 |
|------|------|
| Courses | course_id, title, category, description, cover_url, difficulty, status |
| CourseChapters | chapter_id, course_id, title, content, sort_order, duration_min |
| LearningProgress | progress_id, user_id, chapter_id, completed_at |
| CourseListItem | Course + chapter_count + learner_count + my_progress? |
| CourseDetail | Course + chapters[{..., completed: 0|1}] + progress_pct |

**唯一约束**：`UQ_LearningProgress(user_id, chapter_id)`。
