## 3. 调试问题与解决方案

### 3.1 问题汇总表

| 编号 | 现象 | 原因分析 | 解决方案 |
|------|------|----------|----------|
| BUG-01 | `npm run dev` 弹出「选择打开方式」 | Windows PATH 中 `C:\Windows\system32\npm` 为空文件，优先级高于 Node.js | 使用 `npm.cmd` 代替 `npm`；或调整 PATH 顺序；或使用 `start-dev.bat` |
| BUG-02 | 前端登录返回 500 / 网络错误 | 后端未启动，Vite 代理 ECONNREFUSED | 同时启动 backend 与 frontend；改进 `request.js` 错误提示 |
| BUG-03 | 后端启动失败 EADDRINUSE | 端口 3000 被旧进程占用 | 结束占用进程；`index.js` 增加端口占用友好提示 |
| BUG-04 | 打卡功能 404 | 后端缺少 `/dashboard/clock-in` 路由 | 新增 `ClockInRecords` 表与 dashboard 路由 |
| BUG-05 | 考核页中文乱码 | 使用 sqlcmd 执行 seed.sql，bcrypt 哈希 `$` 被错误解析；重复 seed 导致编码问题 | 改用 `npm run seed` / `npm run reset-db`；seed.sql 增加警告注释 |
| BUG-06 | Windows 身份验证连接失败 | `msnodesqlv8` 原生驱动编译失败 | 回退 SQL Server 身份验证（sa）；重置 sa 密码 |
| BUG-07 | 成员无法访问管理页 | 路由守卫缺失或 Mock 权限未模拟 | 完善 `router.beforeEach` 的 `meta.roles` 检查 |
| BUG-08 | Git push 连接 GitHub 超时 | 网络瞬时不可达 | 重试 push；检查代理与防火墙 |

### 3.2 典型问题详细说明

#### 3.2.1 数据库种子数据写入

**问题**：直接使用 `sqlcmd` 执行 `database/seed.sql` 时，bcrypt 哈希字符串中的 `$` 符号被 shell/SQL 解析器误处理，导致密码哈希损坏，登录失败。

**解决**：编写 `backend/scripts/seed.js`，在 Node.js 环境中调用 `bcrypt.hashSync()` 生成哈希，再通过参数化 INSERT 写入数据库。重建命令：

```powershell
cd backend
npm.cmd run reset-db
```

#### 3.2.2 前后端联调

**问题**：仅启动前端时，所有 API 请求失败。

**解决**：
1. 确认 `frontend/.env.development` 中 `VITE_USE_MOCK=false`
2. 启动 SQL Server 与后端 `npm.cmd run dev`
3. Vite 将 `/api` 代理至 `http://localhost:3000`

#### 3.2.3 端口占用

**问题**：重复启动后端导致 `EADDRINUSE`。

**解决**（PowerShell）：

```powershell
Get-NetTCPConnection -LocalPort 3000 | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

## 4. 设计与实现的讨论和分析

### 4.1 架构设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 前后端分离 | Vue + Express | 职责清晰，便于独立开发与部署 |
| 认证方案 | JWT 无状态令牌 | 实现简单，适合 B/S 单页应用 |
| 数据库 | SQL Server | 实验环境已有，支持事务与外键约束 |
| ORM | 不使用，直接 mssql 参数化 SQL | 降低学习成本，SQL 可控 |
| UI 框架 | Element Plus | 组件丰富，适合管理后台 |

### 4.2 需求变更与实现调整

| 原设计 | 最终实现 | 分析 |
|--------|----------|------|
| 成员自助注册 | 管理员创建账号 | 办公室成员规模可控，减少垃圾账号与审核负担 |
| 邮箱验证码重置密码 | 管理员审核密码找回 | 实验环境无邮件服务；审核流程更符合内部管理 |
| 单一团队列表 | 增加团队总览与加入/退出申请 | 支持成员跨项目团队流动 |
| 无打卡功能 | 新增每日打卡 | 满足办公室日常考勤管理需求 |
| 考核列表 | 增加年月日时间轴筛选 | 便于成员查询历史考核记录 |

### 4.3 实现亮点

1. **Mock 与真实后端双模式**：通过 `VITE_USE_MOCK` 环境变量切换，演示与联调互不干扰。
2. **统一响应格式**：`{ code, message, data }` 便于前端拦截器统一处理。
3. **参数化 SQL**：所有数据库操作使用 `request.input()` 绑定参数，防止 SQL 注入。
4. **幂等设计**：打卡、章节完成、成绩 Upsert 均通过唯一约束或 IF NOT EXISTS 保证重复操作安全。
5. **数据库迁移脚本**：增量迁移与全量 schema 分离，便于版本演进。

### 4.4 实现不足与局限

1. 无真实邮件/短信服务，密码找回依赖管理员人工审核。
2. 课程内容为 Markdown 文本，不支持视频与文件上传。
3. 无分页接口，数据量大时列表性能可能下降。
4. JWT 无刷新机制，Token 过期需重新登录。
5. 未编写自动化单元测试，依赖手工功能测试。

## 5. 算法时间复杂性分析

### 5.1 符号说明

| 符号 | 含义 |
|------|------|
| n | 用户总数 |
| m | 团队总数 |
| t | 某团队任务数 |
| p | 考核周期数 |
| c | 课程数 |
| k | 某课程章节数 |
| d | 动态记录条数 |

数据库索引查询记为 **O(log N)**（B+ 树），无索引全表扫描记为 **O(N)**。bcrypt 哈希/比对记为 **O(1)** 次操作，但常数较大（2^10 轮）。

### 5.2 基本操作时间复杂度

| 操作 | 实现方式 | 时间复杂度 | 说明 |
|------|----------|------------|------|
| 用户登录查库 | 索引 IX_Users_Username / Email | O(log n) | 单次 SELECT |
| 密码 bcrypt 比对 | bcrypt.compare | O(1)* | *常数约 2^10 次哈希轮 |
| JWT 签发/验证 | jsonwebtoken | O(1) | 固定长度 payload |
| 参数化 SQL 执行 | mssql query | O(1) + 查询复杂度 | 网络 + 数据库 |
| 前端路由守卫 | 内存判断 | O(1) | 常数时间 |

### 5.3 各模块核心算法复杂度

#### 5.3.1 认证模块 — 登录

```
步骤：查用户 O(log n) + bcrypt O(1)* + jwt.sign O(1)
总复杂度：O(log n)，瓶颈在 bcrypt 比对
```

#### 5.3.2 仪表盘 — 统计聚合

```
步骤：4 次 COUNT 子查询 + TOP 5 公告 + UNION ALL 动态 TOP 10
单次请求：O(n + m + p + c + d)，近似 O(n)
说明：各 COUNT 独立执行；activities UNION 涉及多表 JOIN
```

#### 5.3.3 打卡 — 每日打卡

```
步骤：SELECT 查重 O(log n) + INSERT O(log n)
总复杂度：O(log n)，唯一索引 UQ_ClockIn_UserDate 保证 O(log n) 查重
```

#### 5.3.4 团队总览 — membership_status 计算

```
步骤：
  1. SELECT 全部团队 O(m)
  2. SELECT 用户申请/成员关系 O(m)
  3. JavaScript Set 构建 O(m)
  4. map 遍历团队 O(m)
总复杂度：O(m)
```

#### 5.3.5 考核 — 时间轴筛选

```
步骤：动态 SQL 拼接 + WHERE YEAR/MONTH/DAY(end_date)
无索引函数扫描：O(p)
有 end_date 索引时：O(p) 至 O(log p + 结果集)
```

#### 5.3.6 考核 — 四维均分计算

```
avg = (tech + team + attitude + contribution) / 4
SQL 层计算：O(1) 每行
```

#### 5.3.7 课程 — 进度计算

```
progress_pct = done / total × 100
步骤：COUNT 章节 O(k) + COUNT 已完成 O(k)
总复杂度：O(k) 每门课程
课程列表页：O(c × k_avg)
```

#### 5.3.8 成绩 Upsert

```
步骤：SELECT 查存在 O(log n) + INSERT/UPDATE O(log n)
总复杂度：O(log n)，唯一索引 UQ_AssessmentScore
```

#### 5.3.9 管理员今日打卡列表

```
步骤：Users LEFT JOIN ClockInRecords，全表 active 用户
总复杂度：O(n)
```

### 5.4 复杂度汇总表

| 模块/接口 | 时间复杂度 | 空间复杂度 |
|-----------|------------|------------|
| POST /auth/login | O(log n) | O(1) |
| GET /dashboard/summary | O(n) | O(1) |
| POST /dashboard/clock-in | O(log n) | O(1) |
| GET /teams/overview | O(m) | O(m) |
| GET /assessments/my-scores | O(p) | O(p) |
| GET /courses | O(c × k) | O(c) |
| GET /courses/:id | O(k) | O(k) |
| POST /assessments/scores | O(log n) | O(1) |
| GET /dashboard/clock-in/today | O(n) | O(n) |

### 5.5 改进设想

| 问题 | 现状 | 改进方案 | 预期效果 |
|------|------|----------|----------|
| 仪表盘多次查询 | 单请求 6+ 次 SQL | 合并为存储过程或单次 CTE 查询 | 减少网络往返，O(n) → 常数次 IO |
| 列表无分页 | 全量返回 | 增加 `page`/`pageSize` 参数与 OFFSET-FETCH | 响应体固定，O(n) → O(pageSize) |
| YEAR/MONTH 函数索引失效 | end_date 函数过滤 | 改用日期范围 `end_date BETWEEN @start AND @end` | 可利用 end_date 索引 |
| 团队总览内存 Set | 前端无关，后端 O(m) map | 数据量大时用 SQL CASE 计算 status | 减少 JS 处理，逻辑下沉 DB |
| bcrypt 登录瓶颈 | 每次登录 ~100ms | 可考虑 argon2 或限制登录频率 + 缓存 | 安全性与性能平衡 |
| JWT 无刷新 | 24h 过期重登 | 引入 refresh token 双令牌机制 | 改善用户体验 |
| 课程进度 N+1 | 列表页子查询多 | 预计算 progress 字段或物化视图 | O(c×k) → O(c) |
| 打卡列表全用户 JOIN | O(n) | 仅查已打卡 + 未打卡分两次或分页 | 大规模用户下可扩展 |
| 无缓存层 | 每次请求打 DB | Redis 缓存公告、团队列表等读多写少数据 | 降低 DB 压力 |
| 无自动化测试 | 手工测试 | Jest/Vitest 单元测试 + Supertest API 测试 | 回归效率提升 |

## 6. 实现阶段总结

本项目在 Windows + SQL Server + Node.js + Vue 3 技术栈下完成了全部功能模块的实现与联调。通过 Mock 模式与真实后端双轨开发，提高了前端迭代效率；通过 Node.js 种子脚本解决了 bcrypt 哈希写入问题；通过参数化 SQL 与 JWT 中间件保证了基本安全性。

当前系统在实验规模（用户数 < 100、团队 < 20）下性能满足需求（页面响应 < 3 秒）。若面向更大规模部署，建议优先实施分页、查询合并与索引优化三项改进。
